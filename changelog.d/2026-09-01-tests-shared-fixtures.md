Consolidated the duplicated scaffolding across `tests/`, from the four-agent simplification review in `.plans/2026-09-01/simplification-review-findings.md`.

New `tests_support_domain` INTERFACE target beside `tests_support`, holding the headers that need nothing above `ksv_domain` — `run_builders.h`, `cerr_capture.h`, `profile_store_files.h`. It exists so `domain_tests` can use them without linking `ksv_data`/Qt, which would drag in the `ksv_copy_mingw_runtime_dlls()` requirement that target is currently exempt from. `tests_support` links it, so its existing consumers pick the headers up transitively.

`tests_support::makeRun(hash, start_time, score, shots, hits, duration)` replaces five byte-identical local `Run` factories (`make_perf`/`make_run`/`makeRun` in profile_builder, profile_service, domain, session_controller and scenario_browser_use_case tests). The other four factories the review listed build different things — samples-carrying runs, or `RunPerformance` — and stay local.

`FakeProfileService` no longer carries twin per-consumer fields: `scenario_list`, `most_recent_perfs_by_hash` and the un-keyed `completion_history` are gone, each accessor now backed by one `ScenarioId`-keyed store (`ScenarioId` identity is the hash alone, so the by-hash and by-`ScenarioId` maps always shared a key). It gained `rolling_time_average` + `rolling_time_average_window_days`, which retires the ~45-line `FakePlaytimeProfileService` that hand-implemented all of `IProfileService` to capture one int. The `getMostRecentRuns` count-truncation contract moved out of the SessionController suite into its own `tests/app/fake_profile_service_test.cpp`.

`DashboardUiTest` and `FirstRunUiTest` now call `App::start()` and read `App::engine()->rootObjects()` instead of re-implementing that block. AGENTS.md notes a new VM has to be added in two places; these copies made it four, so a new required property regressed the tests rather than being caught centrally.

`integration::TestEnv::makeProfileStack()` builds the `FileService -> RunIngestor -> ProfileService` chain `App::App()` builds, next to the temp-dir scaffolding that env already owns; `profile_cascade_test` used to assemble it twice by hand.

Also: one shared `tests/support/qt_gtest_main.cpp` for the app/qt_data/ui suites (integration keeps its own — `QGuiApplication`, `declare_metatypes()`, QSettings redirect); `tests/ui/qml/ItemLookup.js` for the `findByObjectName` walker that was pasted into six `tst_*.qml` files (`TestCase.findChild` genuinely doesn't reach these nodes — the comment recording that moved onto the shared function); `TestDoubles.makeFakeSettingsVm()` for the draft/enable machinery both settings-dialog doubles duplicated, replacing the dead, pre-`SeriesId` `makeFakeGraphVm()`; local `hasError()`, `docObject()`/`writeDoc()`, `makeCanvas()` and `defaultConfig(id)` helpers; and `TEST_P` families for the scenario- and run-sort tests.

`graph_vm_test` addressed two default series by list position (`defaultSeriesConfigs()[6]`, `[1]`) while the rest of the file uses `SeriesId` — reordering the defaults would have silently pointed those tests at the wrong config while their names still claimed score/accuracy. Now looked up by id.

**Integration-suite runtime.** The suites that stood up the whole wired `App` per `TEST_F` now build it once per suite. `PerfPipelineTest`, `CompositionRootTest` and `GraphCanvasGeometryTest` move it (and, for the latter two, the profile await / the fixture decode) into `SetUpTestSuite`; `GraphCanvasGeometryTest` still gives every test its own `GraphCanvas`, since each one repoints the visible columns and y-axis column. `DashboardUiTest` shares one `App` *and* one loaded `Main.qml` scene, resetting the settings dialog and the visible-series set in `SetUp()`; the two tests whose assertions only hold on an untouched scene — one requires the plot subtree to have never been instantiated, the other replaces the profile — moved to `DashboardCleanSceneTest`, which builds its own. Verified order-independent under `--gtest_shuffle --gtest_repeat`. Integration-suite wall time roughly halved.

Two of `CompositionRootTest`'s tests had to be made explicit about their starting point rather than relying on a fresh graph: `SessionController::setCurrentRun` ignores a `run_id` it is already on, so `CurrentPerfChangeCascadesToGraphViewModelReload` now parks on the other fixture first to guarantee its call is a real transition.

`ProfileCascadeTest` no longer copies `VT FlyTS Novice S5.perf` in `SetUp` — no test needed it there, and two deleted it before doing anything.

**Two redundant decodes removed, one of which was hiding a dud assertion.** `PairedPerfAndCsvFixtureProduceOneRunWithCanonicalCsvTotals` spun up a second `ProtoDecoder` to derive the expected score. That fixture's perf and its paired CSV agree on score to 8 significant figures (153.088882), so the derived expectation discriminated nothing — the assertion passed identically against either source, and it is the shots/hits/misses/kills assertions that actually prove the CSV totals won. Now a named constant saying so. The dashboard history test takes its run from `profileService()->getLatestRun()` — the run the pipeline already decoded — instead of decoding the file again.

**Three parked tests came back; their blockers were already fixed.** `PerfPipelineTest`'s `DerivedAccuracyStaysWithinUnitRange` and `ScoreTotalIsTheRunningSumOfPerSecondScore` were parked on `GraphViewModel::fetchData()`'s `entry_id <= 3 / <= 9 -> Column` reconstruction; that mapping is gone, and both pass addressed by `SeriesId`. `SeriesConfigStoreTest`'s `ReorderingToCurrentPositionIsSuccessfulNoOp` was parked because `reorder(PrimitiveMetric, uint32_t)` became `reorder(SeriesId, uint32_t)` — a signature translation. `DashboardUiTest`'s `YAxisTitleLabelTracksTheSelectedColumn` was parked because the axis title didn't follow the selected column; it does now.

`CreateAllocatesMaximumIdThenBecomesExhausted` stays parked, re-checked and re-diagnosed: with `nextComputedSeriesId` at `UINT64_MAX` the first `createComputed()` returns a nullopt `createdId`, so `SeriesConfigStore` refuses to allocate the maximum id rather than allocating it once and only then reporting `ComputedSeriesIdExhausted`. That is a product off-by-one at the boundary, not a test fix, and it now carries a dated `TODO` marker saying so.

`tests/support/kovaaks_dir.h` holds the `<root>/FPSAimTrainer/{performances,stats}` temp-directory layout that `integration_env.h`'s `TestEnv` and `qt_data`'s `FileServiceTest` each had their own copy of. It takes absolute source paths rather than fixture names, so it stays independent of each suite's own `TEST_FILES_DIR`.

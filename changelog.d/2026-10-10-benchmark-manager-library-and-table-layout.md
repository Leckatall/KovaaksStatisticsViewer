Benchmark Manager fixes, in `BenchmarkManagerDialog.qml` and `BenchmarkEditorTable.qml`; no view-model or C++ change.
`ListView#libraryList` rows now emit `doubleClicked`, and the list handles Return/Enter and Up/Down itself (the selection, `selectedEntryFilename`, stays the single source of truth; delegates are `focusPolicy: NoFocus` and a click gives the list the focus). Double-click, Enter and the Open button all call the new `openLibraryEntry(entry)`, which only wraps `vm().openBenchmark(id)` in the existing `runWhenClean`, so unsaved edits raise the same Save/Discard/Cancel guard and an entry that is not `openable` does nothing.
The Library/editor pair is now a `SplitView` with a draggable handle instead of a `RowLayout` whose Library column silently grew to a third of the window (its `Layout.preferredWidth: 260` was overridden by the `Flow` toolbar's implicit width). The toolbar is a single `RowLayout` of content-sized `ToolbarButton`s (the Fusion style's 80px minimum width removed); Refresh and Open directory became icon-only buttons (lucide `refresh-cw`, `folder-open`, added under `qml/icons` and to `src/ui/CMakeLists.txt`) with tooltips and accessible names, and "Import playlist..." became "Import..." (accessible name unchanged). The pane opens at the toolbar's width and its `SplitView.minimumWidth` is that width, so the toolbar can never wrap. A `libraryToggleButton` at the left of the editor header hides the list entirely (`libraryCollapsed`; reset by `open()` and when the draft closes, and ignored while there is no draft) so the table can have the whole window. The no-draft hint moved into the editor pane's area, so the list keeps the same width before and after a benchmark is opened. The mapping panel's label/buttons row is now a `Flow`, so Change/Clear mapping cannot be pushed past a narrower editor.
The add-category and add-scenario controls are `AddRowButton`s labelled "+ Add category" / "+ Add scenario" with tooltips (a `HoverHandler`, because `Control.hovered` is false wherever the platform disables hover effects, including the offscreen driver). The table body (`tableBody`) is capped at its content height (`headerHeight + rows * rowHeight`, plus the scrollbar reserve), so the controls sit directly under the last row; a spacer takes the rest, and a table taller than the editor still scrolls inside the cap. The `+` add-rank, add-subcategory buttons gained tooltips too. `objectName`s (`addCategoryPlus`, `addScenarioPlus`, `addRankPlus`) are unchanged.
The threshold view's horizontal `ScrollBar` is `AlwaysOn` while the ranks overflow (`size < 1`), styled with a track and a lighter thumb, and parented under the body instead of over the last row. The rank header and the body now end together: the add-rank `+` (or its name field) takes a slot of fixed width after the header, and the body keeps a gutter of the same width, so the last header is no longer clipped by the `+`; when all ranks fit, the `+` follows the last rank. Identifying columns are 130/120/200px and rank columns 92px so four ranks fit beside the shrunken Library at the default size.
Latent `TableView` bug fixed on the way, because it made the rightmost ranks unreachable for benchmarks with about nine or more ranks: the threshold view and its `HorizontalHeaderView` gave the three identifying columns zero width, and after a scrollbar jump of more than a viewport `TableView` estimated the new left column from the mixed widths and stopped three columns short of the end. Both views now use one uniform column width and start past the identifying columns through `leftMargin: -hiddenThresholdWidth`, so positions are exact; `contentX = -leftMargin` is the start.
`beginScenarioEdit()` now defers `edit()` until the new row's delegate is loaded (`runPendingScenarioEdit`, retried on the identity view's `bottomRow`/`rows`/`height` changes, expiring after a second): with the table capped at its content a row added a moment ago lies outside the viewport until the layout has grown, and `TableView.edit()` warned "cell to edit is not inside the viewport".
Covered by `tst_BenchmarkManagerDialog.qml` (double-click, Enter, arrow keys, the guard with Discard/Cancel/Save, unopenable entries, one-row toolbar at the minimum width, pane width, library toggle) and `tst_BenchmarkEditorTable.qml` (labels and tooltips, controls under the last row and on screen for a long table, scrollbar visibility and reach for 14 ranks, header/body alignment, add-rank beside the last rank, rankless table).

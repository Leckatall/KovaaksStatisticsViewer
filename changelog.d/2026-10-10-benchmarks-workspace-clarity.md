type: changed
area: Benchmarks
user: The Benchmarks tab opens straight onto your benchmark: the one you last looked at, or the only one you have. Progress toward the next tier is drawn as a bar per scenario, the category breakdown is a table with aligned PB / Recent / Rank / Next tier / Status columns, and rank names appear in their tier colours. Empty categories and the "Resolved" label are gone; a scenario only shows a status when something needs your attention, with a tip on how to fix it. With no benchmarks installed the tab shows one explanation and one "Create or import a benchmark" button instead of three overlapping messages.
---
Default selection: `IBenchmarkTrackingUseCase` gains `selectDefault()`. While nothing is selected it selects the remembered benchmark if it is still a selectable choice, otherwise the only selectable choice when exactly one exists (problem files do not count); otherwise it changes nothing and does not notify. `BenchmarkTrackingUseCase` takes an optional `ISettingsService` (wired in `App::App()`); `select()` remembers the id via the new `ISettingsService::setLastSelectedBenchmarkId` (QSettings key `benchmarks/lastSelectedId` in `qt_data::SettingsService`) and `clearSelection()` forgets it. The use case never auto-selects on its own: `BenchmarkTrackingViewModel::selectDefaultBenchmark()` forwards the request, and `BenchmarkWorkspace.qml` calls it when it becomes visible with the no-selection body (immediately on the tab opening, so the first frame already shows the benchmark) and, deferred with `Qt.callLater`, on creation, view-model change and body change. Creation-time triggers are deferred because inside `Main.qml`'s StackLayout the workspace still reports `visible` while it is created; an immediate check selected and evaluated the benchmark at startup before the tab was opened.
Messages and actions: the header status label (`benchmarkClassificationLabel`) used to repeat `stateMessage` next to every body's own message ("Select a benchmark above…" beside "Select a benchmark to see…"; three "no benchmarks" variants in the empty state). It is now shown only in the trackable state, which has no body message. The header (selector + Manage Benchmarks) is hidden with an empty library, and the Manage Benchmarks button is hidden whenever the body has its own manager action (empty, problems-only, unavailable, incomplete), so only one control opens the manager at a time. The empty library body is a centred title, one sentence and one highlighted "Create or import a benchmark" button. The unavailable message no longer repeats its button's wording.
Next-tier progress: `BenchmarkBlockerList.qml` is a three-column list (scenario, bar, "PB / needed") with a heading naming the next tier. `BenchmarkTrackingViewModel` adds `progress`, `progressColor` and `progressDescription` to each blocker. Progress is measured from the highest threshold the scenario already meets (found in the definition's entry thresholds) toward the required score, not from zero: as a plain ratio nearly every blocker reads as a ~95% bar and the scenarios cannot be told apart. The "N of M scenarios at the next tier" line stays and names the tier in its colour.
Breakdown table: `BenchmarkBreakdownView.qml` measures the widest value of each column over every scenario row of the whole tree (with `FontMetrics` on an inherited-font probe) and passes shared column geometry (`columns`) to every `BenchmarkBreakdownNode`, under a header row (`breakdownHeader_*`). The name column is only as wide as the longest name, so values sit beside their names on wide windows; when the table does not fit, the status column, then the name column, then the other columns (down to their headings) give way and values elide. The old wide/narrow split (`_twoLineMetrics`) is gone. Scenario names line up with their group's name (`groupNameIndent`/`scenarioNameIndent`).
Tier colours: new `readableTextColor()` in `benchmark_format` keeps a benchmark colour when it reaches WCAG 4.5:1 against `darkPanelColor()` (#343434) and otherwise blends it toward white just enough. The breakdown model adds `attainedTierColor`, `nextTierText`, `nextTierColor` and `highestTierColor` roles (as "#rrggbb" or "" because an invalid `QColor` reaches QML as opaque black, which is also why Uncategorized used to show a black swatch); the tracking VM adds `attainedRankColor`, `completedRankColor` and `nextTierColor`, used by `BenchmarkStatusSummary.qml`.
Empty groups: `BenchmarkBreakdownModel::buildTree` always pushed an Uncategorized node and every category/subcategory. It now skips Uncategorized when the definition has no uncategorized entries and any category or subcategory holding no scenarios (counting through subcategories). New `scenarioCount` role; group rows show "N scenario(s)" from it instead of the child count, which counted subcategories as scenarios.
Match status: `matchStateLabel` returned "Resolved" for every normally matched scenario. Resolved now yields empty text; the abnormal states read "No runs of linked scenario", "Not found in your runs", "Several scenarios match" and "Linking to your runs…", and a new `matchStateHint` role says what to do (shown as the status cell's tooltip and accessible description). With no abnormal state, a blocking scenario's Status cell reads "Blocks next tier".
The trackable and incomplete scroll views use `ListScrollBar` (positioned explicitly, since a ScrollView leaves a replacement bar's geometry to the caller), so the breakdown below the fold reads as scrollable.
Tests: `BenchmarkTrackingDefaultSelection.*` in `benchmark_tracking_use_case_test.cpp` (only one, several, problem files, remembered, remembered-but-gone, existing selection, remember/forget, new-session round trip, no settings); `SettingsServiceTest.LastSelectedBenchmarkSurvivesARestartAndCanBeCleared`; breakdown model tests for hidden empty groups, scenario counts, readable tier colours, abnormal-only match states and unplayed/unmatched scenarios; tracking VM tests for `selectDefaultBenchmark`, summary colours and blocker progress; `tst_BenchmarkWorkspace.qml` for default-selection triggers (including not selecting while hidden), one manager action per state, no repeated messages, header status only while tracking, column alignment under headers at both widths, abnormal-only status, tier colours and progress bars. `benchmark_composition_test.cpp` expectations updated for the new match-state wording.

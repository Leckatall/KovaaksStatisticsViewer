---
type: fixed
area: Graphing
user: Graphs are easier to read. Axis labels no longer repeat or get cut off at the edges. The run graph says which line its Y-axis numbers belong to, and its line toggles now sit inside the graph panel, in the lines' exact colours. Run history marks each run with a dot when there are few runs and no longer labels a run "#0". The playtime graph shows a message instead of empty axes when there is no playtime, and the run graph no longer shows a "1970-01-01" date when no run is selected.
---
Per-run graph title: `GraphUseCase::get_run_label()` returned `run_id.toString()` even with no current run, and a default-constructed run id formats its zero start time as the epoch, so the title read "(1970-01-01, 01:00:00)". It now returns an empty string when `hasCurrentRun()` is false (documented on `IGraphUseCase::get_run_label`), and `DashboardGraphCanvas.qml` falls back to a neutral "Run graph" title.
Playtime empty state: `PlaytimeGraphViewModel` gains a `hasData` property (notified by `dataUpdated`). `PlaytimeGraphPanel.qml` loads its `GraphCanvasWithTooltip` through a `Loader` only when there is data and otherwise shows "No playtime recorded yet." in the same slot, so the panel keeps its size and draws no grid or axes.
Repeated tick labels: `ValueAxis` picked a nice step from the numeric range alone, so a sub-unit range with a whole-unit formatter (the empty playtime graph: 0..2 minutes in 0.2 steps, labelled with `std::round`) produced "1 min" six times and "0 min" five times. `ValueAxis::recompute()` now checks the formatted labels and coarsens the step along the 1-2-5 sequence (`nextNiceStep`) until no two adjacent labels are equal (bounded by `kMaxCoarsening`). Tick generation was split into `resolve(lo, hi, step)`.
Day-granular date axes: `DateTimeAxis::Options::wholeDays` skips sub-day calendar intervals; the playtime VM and the benchmark history axis (`BenchmarkTrackingViewModel::m_historyXAxis`) use it, since their data is one point per day and short ranges used to tick every few hours. Sub-day labels now show only "HH:mm", with the date on the first tick and at midnights, so they are short enough to fit.
Clipped tick labels: `AxisPainter` drew every horizontal label in a fixed 40px box centred on its tick ("Oct 9 00:00" became "ct 9 00:0") and vertical labels in a fixed 16px box. New `AxisPainter::layoutLabels()` measures each label, centres it on its tick, shifts it inwards to stay inside the canvas `bounds` (new `paint` parameter), and when neighbours would overlap labels only every n-th tick, using the smallest stride that keeps a gap. Grid lines are still drawn for every tick. This also applies to the two Benchmarks-tab graphs, which share `GraphCanvas`.
Line toggles: `ControlPanel` is no longer a separate `GridLayout` column in `ScenarioWorkspace.qml`; `DashboardGraphCanvas.qml` hosts it as a wrapping `Flow` row under the title and forwards `configureLinesRequested`. Each toggle's indicator is a swatch in the series colour at full opacity (filled when the line is shown, outlined when hidden). Previously the whole chip background was the series colour at 50% opacity. The label uses the normal palette text colour, so it stays readable on every series colour. The View menu entry "Control Panel" is renamed "Graph Line Toggles" and still drives `controlPanelVisible`.
Y-axis ownership: `GraphCanvas` exposes `labelledYAxisColumns` (the labelled series plus any visible series that shares its `yAxisId`), `hasIndependentlyScaledSeries` and `labelledYAxisColor` (the series colour lightened by `AxisPainter::legibleOn` to WCAG 4.5:1 on `backgroundColor`). When other lines are independently scaled, the Y tick labels, the axis line and the rotated axis title take the labelled line's colour, the lines on that axis are drawn last, and the run graph shows a caption ("Y axis: Score · other lines are each scaled to fit; hover for their values"). `CompletionHistoryViewModel` now sets `yAxisId` from its axis metadata so Shots/Hits/Misses are recognised as sharing one axis.
History markers: `GraphCanvas::pointMarkers` (opt-in, set by `ScenarioHistoryPanel.qml`) draws a dot on each real sample when consecutive points average at least `kMinMarkerSpacing` (10px) apart (`markersFit`), so 8 runs are dotted and 224 stay a plain line; `pointMarkersShown` reports the result. `SeriesPainter` markers default to the line colour with a background-coloured outline, and a lone point is always drawn as a marker. Before this, it was skipped because a curve needs two points.
History X axis: the run axis used `Baseline::Zero` with nice bounds, so it started at "#0". New `ValueAxis::Options::niceBounds = false` keeps the bounds at exactly the data range and ticks only the nice multiples inside it; `CompletionHistoryViewModel` uses it with `HugData` over `1..runCount`, so every label is a real run and few runs get one tick per run.
Tests: degenerate-range label tests in `value_axis_test.cpp` and `date_time_axis_test.cpp` (zero span, sub-unit span, single point, range sweeps); `AxisPainterLayoutTest` (no clipping, thinning, single tick, `legibleOn`); `GraphCanvasGeometryTest` axis-ownership and `GraphCanvasMarkersTest`; `SeriesPainterTest` marker defaults and single point; VM tests for playtime `hasData`, day ticks and history run axis; `GraphUseCaseTest` empty run label; QML tests `tst_PlaytimeGraphPanel.qml` (new), `tst_ControlPanel.qml`, `tst_DashboardGraphCanvas.qml`, `tst_ScenarioHistoryPanel.qml`, `tst_AppMenuBar.qml`.

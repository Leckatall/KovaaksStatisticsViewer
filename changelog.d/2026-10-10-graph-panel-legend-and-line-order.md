Follow-ups to the graph rework in 112cc47, all within the Scenarios tab's three graph panels.
Coloured Y axis removed: `GraphCanvas::drawAxes` no longer passes a series-coloured `AxisPainter::Style` (text colour + axis line) when other lines are independently scaled; the "Y axis: … · other lines are each scaled to fit" caption row (`yAxisScaleCaption`) is gone from `DashboardGraphCanvas.qml`, and `YAxisTitle` is back to its fixed grey (its `textColor` property is reverted). Deleted with them: `GraphCanvas::hasIndependentlyScaledSeries`, `labelledYAxisColor`, the private `AxisOwnership`/`axisOwnership()`, `AxisPainter::legibleOn` (and its WCAG luminance helpers), `AxisPainter::Style::axisLineColor`, the `GraphCanvasWithTooltip` pass-throughs and their tests. `labelledYAxisColumns` stays and still feeds the axis title text.
Line order: `GraphViewModelBase::series()` now returns series in the graph's line-list order whatever order the columns are requested in. `GraphViewModel::series()` used to iterate `QMap<QString, SeriesModel*>` keyed by id string (lexical, so "10" came before "2") and now iterates `m_allSeriesList` (series config order, the order `enabledSeriesIds` and the legend show); `fetchMetadata()` clears that list before deleting the models so it never holds dangling pointers. `CompletionHistoryViewModel::series()` used to follow the requested column order and now walks Score..Misses. `GraphCanvas::drawSeries` previously moved the labelled-axis lines to the end; it now paints `seriesInPaintOrder()` (the list reversed) so the first series in the list is painted last, on top, with its markers. `GraphCanvas::paintOrder()` exposes the columns in that order for tests.
Hover dots in `GraphCanvasWithTooltip.qml` get `z` by index (earlier = higher) so they stack the same way, while the shared `hoverInfo.series` list (and the tooltip text) stays top-of-list first. The hover `MouseArea` and dots carry objectNames `graphHoverArea`/`graphHoverDot` for tests.
Legend: `ControlPanel.qml` is now a vertical column (a `Flickable` of chips with a vertical `ScrollBar` that appears only when the chips overflow, then a flat "Configure..." button pinned below). It reports only one row of implicit height so it never decides the panel height; its implicit width is the widest chip, with chips capped at `maximumChipWidth` (200px) and their labels elided. `DashboardGraphCanvas.qml` puts it in a `RowLayout` beside a column holding the title and the plot, so it spans the full inner height and the title centres over the plot; `controlPanelVisible` still hides it and the plot takes the full width.
Equal panels: in `ScenarioWorkspace.qml` the three panels each get `Layout.preferredHeight: 1` alongside `fillHeight`, so the `ColumnLayout` grows them in equal ratio instead of favouring the largest implicit height (the run panel); hidden panels drop out and the rest split equally. The panels now have objectNames `scenarioGraphPanel`, `playtimeGraphPanel`, `scenarioHistoryPanel`.
Tests: `GraphViewModelTest.SeriesFollowTheLineListOrder`, `CompletionHistoryViewModelTest.SeriesFollowThePlottableColumnOrder`, `GraphCanvasGeometryTest.LinesArePaintedBottomOfTheListFirst`/`PaintOrderReversesTheEnabledLineList`, `DashboardUiTest.HoverDotsStackInLineListOrder`/`GraphPanelsShareTheColumnEqually`; QML layout tests for the legend column, scrolling, eliding, flat button, title centring and grey axis titles in `tst_ControlPanel.qml`, `tst_DashboardGraphCanvas.qml`, `tst_ScenarioHistoryPanel.qml`.

Changes in the Scenarios workspace's left column and its workspace-level first-run state (the graph panels and the "Lines" toggles are changed separately, in the graphs fragment).
`ScenarioRunItem.qml`: the ~60px two-line rounded card ("Pasu Gallery (2026-08-15, 12:49:00)" / "Score … Acc …" / PB badge) became a 24px single-line row (`rowHeight` = label height + 8) with columns date/time | score | accuracy | PB, zebra striping, and an accent bar + border for the current run. The scenario name is shown only in Recent (`showScenarioName`, from the new `scenarioName` role) since a scenario's own list already names it in its header; the full run label and hits/shots are in a hover tooltip and the row's `Accessible.name`. PB rows also bold the score.
`RunListView.qml` measures the column widths with hidden probe `Label`s (same font as the rows), shows a "Played / Score / Acc / PB" column header aligned with the cells, exposes `rowHeight`, `runCount`, `scrollable` and `heightForRows(n)`, places the empty text at the top of the list area, and uses the new `ListScrollBar.qml`. Object names `runItem_N`, `runScore_N`, `runAccuracy_N`, `personalBestBadge_N` are kept; `runLabel_N` is replaced by `runDate_N` / `runScenario_N`.
`SelectionPanel.qml`: expanded Recent is sized to a whole number of rows (`heightForRows`), between 3 and 6 rows and at most ~25% of the column, so it never ends through a row's text and never squeezes the lists below; it scrolls with an always-visible scroll bar when it holds more, and the toggle shows the count ("Recent (10)"). The scenario section and the run list share the rest with vertical stretch factors 2:3 and minimum heights of a few rows; the scenario section is capped at its fitted height (`ScenarioSearchPanel.fittedHeight`) so a short catalogue leaves the room to the runs.
`ListScrollBar.qml` (new): Fusion's scroll bar handle is nearly invisible on the dark palette and auto-hides; this one is `AlwaysOn` while the list overflows, with a visible handle. Used by both run lists and the scenario list.
`SortControls.qml` is now one row: "Sort by" label, combo box (`WidestText` width), and a direction button reading "▼ Desc" / "▲ Asc" with a tooltip ("Sorted descending (highest, newest or Z first). Click to sort ascending."), `Accessible.name` "Sort direction: descending|ascending" and `Accessible.description`. Both labels are laid out in the button's content item so flipping never changes its width, and the button no longer takes Fusion's 80px minimum. `ScenarioSearchPanel.qml` gained a "Scenarios" header row holding its sort controls, mirroring the run list's "<scenario> … Sort by" header, with the search field below. `directionToolTip`/`directionToolTipShown` are exposed for tests.
`ScenarioSearchPanel.qml`: the empty state moved from a label under the list (it ended up at the bottom of the window) to the top of the list area, with "No scenarios yet" and a hint that runs are imported from the Kovaaks folder automatically and where to check the folder (File › Set Source Directory). A search with no matches says so and suggests clearing the search instead.
New `FirstRunWelcome.qml`, shown by `ScenarioWorkspace.qml` instead of the column/graph grid when `kovaaksFolderSet` is false (bound to `SettingsViewModel.kovaaksDirSet` in `Main.qml`) and the VM's `hasScenarios` is false: a centred card with a welcome title, one sentence of explanation, a filled accent "Choose Kovaaks Folder…" button (emits `chooseKovaaksFolderRequested`, wired to the existing folder dialog) and a hint naming the FPSAimTrainer folder. If runs exist without a configured folder (an existing profile, or the default Steam path), the workspace is shown as before. `Main.qml`'s thin `FirstRunBanner` now hides while the welcome is shown, so it does not repeat it or shift the tab bar when switching tabs; it still covers a folder-less setup that has runs.
Tests: `tst_RunListView.qml` (row pitch at most half the old 66px, one-line columns aligned across rows, Recent scenario column, accessible summary, whole-row sizing and scroll bar), `tst_SortControls.qml` (state text/accessible name flip without resizing, hover tooltip, label on the combo row), `tst_ScenarioSearchPanel.qml` (empty state position and guidance, no-match message, externally driven highlight), `tst_SelectionPanel.qml` (VM-driven active scenario; bounded whole-row Recent with the lists still showing several rows at 1000x640-like size), new `tst_FirstRunWelcome.qml`, and `tst_Main.qml` (welcome replaces graphs and banner on first run, banner hidden on the Benchmarks tab without moving the tab bar, workspace shown when runs exist or a folder is set). `dashboard_ui_test.cpp`'s first-run test now accepts whichever single prompt applies (welcome when nothing is imported, banner otherwise) and checks both hide after a folder is chosen.

New dev-only UI automation driver so agents can see and drive the real UI: `ksv_driver` (`tools/driver/`) plus the `scripts/ui_driver.py` CLI (`scripts/ui_automation/`). Reference: `tools/driver/README.md`.
`ksv_driver` builds the real `App` graph through the injecting constructor against a disposable session dir (`.temp/ui-driver/<session>/`).
Every QSettings (SettingsService and QML `Settings {}`) and AppDataLocation is redirected into the session, the same way as in `tests/integration/qt_test_main.cpp`.
Sessions are seeded from the gallery's synthetic profiles plus a generated two-category demo benchmark, or from the `tests/examples` fixtures through the real import pipeline, or left empty / first-run.
Main.qml is loaded by its qrc URL through `gallery::QmlSourceInterceptor`, which was extracted from `gallery_main.cpp` into `tools/gallery/qml_source_interceptor.h`. QML therefore comes from `src/ui/qml` on disk, and `ui_driver.py restart` picks up QML edits without a rebuild; `--compiled-qml` uses `App::start()` instead.
`App::initialProperties()` now returns the 8-VM required-property map that `App::start()` hands to the engine, so the driver can load Main by URL.
`ksv_driver_core` (`UiDriver`) does all inspection and input in-process, which is what makes it work headless:
- It walks every `QQuickWindow`; Settings and Benchmark Manager are separate `ApplicationWindow`s. Items are walked through `childItems()`, and popups through the QObject tree of whatever declared them.
- Selectors are objectName globs or `id:`/`text:`/`type:`/`acc:` terms, with `a > b` descendants, `@N` picks and `win:` scoping. Ambiguous matches report their candidates; misses report similar names and hidden matches.
- Input is real synthesized `QTest` mouse/key events and `QWheelEvent`s, sent once the target window is exposed.
- It also provides `QQmlProperty` get/set, JS `invoke` and `QQmlExpression` `eval` in Main.qml's scope, `wait` polling, and `QQuickWindow::grabWindow()` screenshots, optionally cropped to an item.
- A `MessageLog` ring buffer captures Qt log messages, so each command returns the warnings the app logged while it ran.
`DriverServer` speaks newline-delimited JSON on a `127.0.0.1`-only `QTcpServer` and queues requests that arrive while a command spins the event loop.
Headless runs use the offscreen QPA, which has no fonts and ignores the dark colour scheme, while Qt Quick Controls take their palette from the platform theme. `driver_main.cpp` therefore points `QT_QPA_FONTDIR` at the Windows fonts, sets Segoe UI 9pt, and writes a snapshot of Qt 6.12's Windows dark palette into every window's `palette` colour groups, so headless screenshots match the native app.
The driver builds with `ksv_gallery` under the existing `KSV_BUILD_GALLERY` non-Release gate, whose option text now names both tools. The root `find_package(Qt6)` now also asks for `Network`. `gallery_dataset.*` became the `ksv_gallery_support` static lib shared by both tools.
`build_and_test.py` gained a repeatable `--target NAME` option, valid only with `--build-only` and the default scope, to build specific CMake targets. `ui_driver.py start --build` uses it.
Tests: `tests/integration/driver_ui_test.cpp`, added only when `ksv_driver_core` exists, covers selectors, hidden-page filtering, ambiguity, clicks, typing, dialog windows and screenshots against the real Main.qml. `scripts/tests/ui_automation/` covers the CLI request mapping, the socket client, session handling and output formatting.

UI driver screenshot sessions become repeatable tours with contact sheets. Reference: `tools/driver/README.md` ("Batches and tours", "Composing a session").
Named shots: `shot --name LABEL [--dir SUBDIR]`, and `--shot=LABEL` / `--shot-dir SUBDIR` on any action (the CLI rewrites `--shot=LABEL` into a hidden `--shot-name`, so a bare `--shot` keeps its old meaning in any position). Numbers keep counting across subdirectories (`session.next_shot_path`). Every shot saved under the shots root appends a line to `shots/index.jsonl`: path, label, dir, window, size, the CLI line that took it, a UTC timestamp and the app warnings printed for that command.
`report [DIR]` (new `scripts/ui_automation/report.py`, standard library only) writes a self-contained `index.html` in the sweep sheet's layout: a dark responsive grid of `minmax(300px, 1fr)` cards grouped by subdirectory, captions from labels plus command and warnings, a failed-steps table from a tour's `summary.json`, and a coverage table from `coverage.json` (`[{area, state, shot}]`), each state marked captured or missing by shot label. Images are embedded as data URIs (`--link` links them); a small inline script enlarges a shot on click. Without `index.jsonl` it lists numbered PNGs.
`batch` gained `set NAME=value` with `${NAME}` substitution (predefined `BATCH_DIR`, `REPO`, `SESSION`; an unknown variable fails the step), `section NAME` (default shot subdirectory), `options --keep-going --fail-on-warnings`, lifecycle `start`/`restart`/`stop` lines on the batch's own session (handled before the batch parser, which still rejects lifecycle commands), `--var`, and `--fail-on-warnings`. It always ends with a summary of steps and failures and exits 1 when any step failed, also under `--keep-going` (it used to exit 0 there).
`start` now prints the warnings the app logged while loading (`logs --all --warnings`, minus offscreen-QPA chatter), so a QML binding error at load time is visible and fails a `--fail-on-warnings` batch.
`tour NAME [--report]` runs `tools/driver/tours/NAME.txt` in session `tour-NAME` with `${TOUR_DATA}` pointing at `tools/driver/tours/NAME/`, keeps going by default, stops the session afterwards, and writes `shots/`, `summary.json` and the report under `.temp/ui-driver/tours/NAME/` (outside the session, so the tour's `start` lines can re-seed it).
Checked-in tours: `smoke` (every dataset's main screens at 1280x800 and 960x700 with `--fail-on-warnings`; about 20 s; verified to fail on an injected QML binding error), `full` (the 2026-10-11 sweep's reachable states, named), `unreachable` (all 22 states the sweep could not reach, using only `--setting`, `--profile-spec`, `--overlay`, `--inject`, `rm`/`edit`, `mouse` and dialog window keys) and `composing-example` (the README's worked example: unresolved and ambiguous benchmark rows from a spec plus an overlay). `scripts/tests/ui_automation/test_ui_driver_tours.py` parses every checked-in tour line and coverage file.
`--shot` after `key`/`type`/`mouse`/`resize` now screenshots the window the command reported instead of falling back to `main`.
The spec benchmark generator leaves a category entry unhashed when its name matches several scenarios (it used to take one of them), so a spec alone can produce an ambiguous row.

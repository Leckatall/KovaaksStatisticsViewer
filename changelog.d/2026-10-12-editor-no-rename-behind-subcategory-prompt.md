---
type: fixed
area: Benchmarks
user: In the Benchmark Manager, naming a new subcategory and pressing Enter no longer also opens a rename box on the category behind the "category already holds scenarios" question; after you answer it, the new subcategory (or the category, if you cancel) is selected.
---
Old bug in `BenchmarkEditorTable.qml`: `subcategoryCreationField` (inside the cell delegate's `face`) handled Return in `onAccepted`, but `TextInput` emits `accepted()` and leaves the key event unaccepted, so Return propagated up the item tree to `identityView`, whose `TableView` edit-key trigger opened the rename editor on the current cell, the category. When the category already held scenarios, `BenchmarkManagerDialog.requestSubcategory` had just opened the modal `subcategoryRelocationPrompt`, so the editor sat behind it holding the category name.
Second problem in the same flow: the prompt saved the field as the focus to restore, the field was hidden by then but stayed `identityView`'s focus-scope child, so closing the prompt (or any later `identityView.forceActiveFocus()`, which `moveCurrent` uses) handed active focus to an invisible field.
Fix: the field takes Return/Enter with `Keys.priority: Keys.AfterItem` and accepts it after `TextInput` has emitted `accepted()`; before sending `addSubcategoryRequested` (and on Escape) it clears its own `focus` and focuses the table, refocusing itself only if the request was refused (`creationAccepted` false).
`subcategoryRelocationPrompt` now records the group to focus (`focusGroupAfterClose`): the category on open, the `createdId` of `addSubcategoryRelocating` after a choice; `onClosed` calls `editorTable.focusCell({groupId})` via `Qt.callLater`. So Cancel/Escape end on the category cell, "Move them into" on the new subcategory's cell, "Move them to Uncategorized" on the new (empty) subcategory's group-list entry.
Other inline fields checked in the driver: category creation, rank creation, the empty-group subcategory/rename fields (group list) and the rank-header rename editor do not leak Return into anything that opens an editor; the cell edit delegate's Return is handled by `TableView` itself.
Tests: `tst_BenchmarkEditorTable.qml` `test_returnInSubcategoryFieldOpensNoRenameEditor` (fails before the fix: an editor opens on Return), `tst_BenchmarkTableManagement.qml` `test_subcategoryPromptOpensNoEditorAndReturnsFocusToTheTable` (fails before the fix: focus is left in the hidden field); `openTableDialog` there takes an optional `fixtureRef`.

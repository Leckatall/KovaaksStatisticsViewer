type: fixed
area: Benchmarks
user: In the Benchmark Manager, opening a benchmark with longer rank names than the one shown no longer leaves its rank columns scrolled part-way into the first rank: the first rank starts right after the Scenario column.
---
Old bug: `setProjection` resets `BenchmarkTableModel` on any shape change (another benchmark opened, a rank or row added or removed). The reset re-measures `rankHeaderMinimumWidth`, so `thresholdWidth` changes and `relayoutRankColumns()` (via `Qt.callLater`) put `thresholdView.contentX` at `rankScrollStart + scrolledRanks * width`, which was correct. But that relayout ran before the threshold view had processed the reset (`thresholdView.columns` still held the old count). The view's own rebuild for the reset then came afterwards and kept its scroll position as a fractional column at the width laid out before it, scaling `contentX` by new width / old width. Going from the driver's Demo benchmark (76-77 px ranks) to Driver Many Tiers (95 px), 285 became 285 × 95/77 ≈ 351.6, about 0.75 of a rank past the start. `clampRankScroll()` left that alone because it was still inside [`rankScrollStart`, `rankScrollStart + rankScrollRange`]. Narrower ranks were not affected (the relayout's position held), and neither were reopens at the same width.
`BenchmarkEditorTable.qml`: on `modelAboutToBeReset`, `noteRankScrollBeforeReset()` records the ranks scrolled past the first at the laid-out width in `rankScrollOnReset`. `restoreRankScrollAfterReset()` puts the view back at `rankScrollStart + min(ranks * thresholdWidth, rankScrollRange)` and clears the note. It runs from `thresholdView.onLayoutChanged` and from `relayoutRankColumns()`'s same-width path, but only once the view's `columns` match the model's `columnCount()`, the laid-out width is current, and no cell editor is open. `relayoutRankColumns()` measures from the note instead of the possibly rescaled `contentX` while it is pending, and clears it if the view has already caught up with the model.
So a reset keeps whole ranks scrolled past (none leaves the first rank right after the Scenario column), matching what the width-change relayout already did.
Tests: `test_resetToWiderOverflowingRanksKeepsWholeRanksScrolled` (tst_BenchmarkEditorTable) covers resetting from fewer fitting ranks and from as many narrower ranks to wider overflowing ranks, both unscrolled and two ranks scrolled. All three cases fail without the fix (contentX 1942.75 against 786 / 1310).

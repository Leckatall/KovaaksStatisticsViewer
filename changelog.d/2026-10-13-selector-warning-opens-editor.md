user: On the Benchmarks tab, a benchmark marked incomplete, invalid or unsupported has an edit button beside its label that opens the Benchmark Manager on it: an incomplete benchmark opens in the editor, a broken file is shown selected in the library. It works on rows that can't be selected and doesn't select them.
---
`BenchmarkWorkspace.qml`: every selector row whose classification is not trackable gets an icon-only `ToolButton` (`selectorEntryEdit_<name>`, new lucide `icons/square-pen.svg`) right of its chip (`selectorEntryLabel_<name>`, now anchored to the button instead of the row edge). Its text, accessible name and tooltip are "Edit <name> in the Benchmark Manager" for incomplete rows and "Show <name> in the Benchmark Manager" for invalid/unsupported ones. It is declared after the row's click-blocking `MouseArea`, so it stays clickable on disabled (unselectable) rows, and it never calls `selectBenchmark`.
The button raises a new `editBenchmarkRequested(filename, benchmarkId)` signal from the selector entry's `filename` and `id`, which `BenchmarkTrackingViewModel::selectorEntries` already published; a problem file's id is empty, so the filename is the key.
`Main.qml` routes it to the new `BenchmarkManagerDialog.openOnEntry(filename, benchmarkId)`: it runs the existing `open()` (which clears the library selection), then selects the matching library entry by filename (falling back to id when no filename is given), scrolls the list to it and, for an openable entry, opens it through `openLibraryEntry` and so through the unsaved-changes guard. A draft of the same benchmark already open from the library is left alone so its unsaved edits survive; an unknown entry only opens the manager.
No view model, use case or C++ changed (ADR 0004): the workspace hands an identity it got from its own use case to the dialog, which acts through `BenchmarkManagerViewModel`'s existing `openBenchmark` over `IBenchmarkManagerUseCase`. Both read the same `BenchmarksService` library snapshot, so the filenames agree.
The warning pages' own buttons ("Edit benchmark", "Manage benchmark files", "Open the Benchmark Manager") are unchanged and still call the plain `open()`.
Tests: `tst_BenchmarkWorkspace.qml` (control visibility, placement, accessible name and tooltip per classification; click emits filename + id without selecting), `tst_BenchmarkManagerDialog.qml` (`openOnEntry` for openable, problem, id-only, unknown, same-draft and dirty-other-draft cases), `tst_Main.qml` (the signal opens the shared dialog on the entry). The tracking-VM fixtures in `TestDoubles.js` now carry `filename` like the real selector entries.

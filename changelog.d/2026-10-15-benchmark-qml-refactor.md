Phase 0: `src/ui/qml/` regrouped by feature with `git mv` — `shell/`, `scenario/`, `graph/`, `series/`, `benchmark/`, `common/`; `Main.qml` stays at the root because the integration tests read it by path.
`QML_FILES` in `src/ui/CMakeLists.txt` updated, icon paths in moved files now `../icons/…`.
Every QML file in the module gains `import KovaaksStatsViewer`: the compiled module already sees cross-folder types through the per-directory qmldirs (`QTP0004`), but `ksv_gallery`, `ksv_driver` and the QML test suites load files from disk, where a file implicitly imports only its own directory.
The QML test suites' directory imports (`import "../../../src/ui/qml"`) now name the subfolder holding the types each test uses.
A1: group-structure rules the QML derived from raw `groups` arrays are computed in C++. `BenchmarkManagerViewModel::groups` entries carry `acceptsScenarios` (and, on categories, `subcategoryNeedsRelocation`), a new `assignTargets` property lists Uncategorized then every group that accepts scenarios, `BenchmarkTableModel::rowInfo()` adds `positionInContainer` / `containerSize`, and `BenchmarkProgressGridModel::groups` entries carry `spansSubcategory`.
`canDropOn()`, `assignTargets()`, `currentRowPlacement()`, `requestSubcategory()` and the grid's `spansSubcategory()` now read those fields; GoogleTests cover each, and the plain-JS test doubles supply them.
A2: `BenchmarkEditorTable`'s `addCategoryRequested` / `addSubcategoryRequested` / `addRankRequested` signals and the `creationAccepted` flag the dialog wrote back are replaced by one `creationHandler` property, a synchronous `(request) => bool` taking `{kind: "category" | "subcategory" | "rank", …}`; with no handler set, creation is rejected. The Manager dialog dispatches it to its existing `addCategory` / `requestSubcategory()` / `addTier` logic.
A3: `BenchmarkEditorTable` sets `focusedGroupId` itself on a group cell's or group-list button's right-click before emitting `groupContextRequested` (the rank header already focuses itself, setting `focusedTierId`), so the Manager dialog's context handlers only pop up the menus. `requestLinkedVersion()` builds the new hash list from `currentRow.mappedHashes` rather than the mapping panel, and `benchmarkNameField` is a `BoundField` instead of an inline copy of its `Binding`.
B1: new `common/Theme.qml` singleton (registered with `QT_QML_SINGLETON_TYPE`) holding the shared colours (`errorText`, `error`, `warning`, `attention`, `success`), `toolTipDelay` / `shortToolTipDelay`, `groupTintAlpha`, `classificationColor()`, `readableOn()` and `isLightFill()`; the benchmark files, `SeriesConfigDraftPanel` and `SettingsDialog` use it instead of their literals, and `BenchmarkProgressGrid.readableOn()` forwards to it.
One visual change: the benchmark selector's Incomplete chip is now `#FFA726`, the Manager's Incomplete colour, instead of `#FFB74D`.
B2: new `common/CreationField.qml`, a `TextField` for naming a new category, rank or subcategory: it calls its `submit(name)` handler, clears and emits `done()` when that returns true, keeps its text when it returns false, ignores blank input, and clears and emits `done()` on Escape. The four creation fields in `BenchmarkEditorTable` use it; the category cell's field sets `focusReturnTarget` (focus moves to the table before submitting and returns to the field on rejection) and `swallowReturn`.
The empty-group subcategory field now exposes its placeholder as its accessible name, as the other three already did.
B3: new `common/ToolbarButton.qml` (the Manager dialog's former inline `ToolbarButton`) and `common/TooltipToolButton.qml`, a `ToolButton` whose tooltip shows while a `HoverHandler` reports hover and the tooltip text is non-empty. The table's `AddRowButton` (still an inline component, now deriving from it), the add-rank, category-cell and empty-group "+" buttons and the Workspace's `entryEditButton` use it.
One minor change: `entryEditButton` previously used `hovered`, so its tooltip now also works where the platform disables hover effects.
B4: new `common/GridHeaderCell.qml` (a `Rectangle` header cell with `text`, `alignment`, `labelPadding` and a `focused` 2px highlight border) and `common/GridCellBorders.qml` (the 1px bottom and right lines). The editor table's identity headers, empty rank header and rank header background, and the progress grid's header cells use `GridHeaderCell`; the table's `TableCell` face and the grid's group cell use `GridCellBorders`.
The progress grid's inline `HeaderCell` remains as a thin derivation of `GridHeaderCell` that keeps its column-header accessibility role and name. The identity headers now elide and keep a 6px right margin like the grid's headers; their widths already fit the text, so nothing renders differently.
B5: new `common/OverflowScrollView.qml`, a `ScrollView` with `contentWidth: availableWidth`, `clip: true` and the always-visible-when-overflowing `ListScrollBar` wired with its own geometry. The Workspace's incomplete and trackable bodies use it; ids and the `benchmarkWorkspaceScroll` object name stay on the instances.

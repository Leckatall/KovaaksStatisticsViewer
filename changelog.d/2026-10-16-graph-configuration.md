---
type: added
area: Graphing
user: Each graph gets a gear popup and a Graphs settings page for choosing its date or run range, playtime averaging window, line style and markers, series colours and widths, and how its axes fit.
---
`GraphConfiguration` (`src/app/contracts/graph_configuration.h`, `ksv_contracts`) — Qt-free value snapshot of per-graph preferences keyed by `GraphKey` (`run`, `dailyPlaytime`, `scenarioHistory`, `benchmarkRank`, `benchmarkPlaytime`) plus the Graph Lines `RunSeriesDocument` and the run graph's Y-axis-label series. Ranges are a variant of all history, recent days, inclusive `year_month_day` custom dates and latest runs (scenario history only); appearance is a connection mode plus a separately kept line-mode marker preference; series colour/width overrides and numeric axis policies (fit visible, start at zero, fixed bounds) are keyed by stable local series/axis keys from `graphDescriptor()`.
Defaults reproduce the existing look: all history, three-day playtime averaging, smooth lines with markers only on scenario history, the existing series colours at SeriesPainter's width 3, fit-to-data score/accuracy axes and zero-based counts/playtime axes, no generic fitting for the rank or run graph.
`validateGraphPreferences()` / `validateGraphConfiguration()` return issues keyed by graph, group (`dataRange`, `axes`, `seriesStyle`, `graphLines`), series/axis key and field, rejecting inapplicable or missing fields, invalid or reversed dates outside 1970-01-01..9999-12-31, non-positive or over-limit day/run/window counts, non-finite or out-of-range widths and bounds, and fixed bounds whose minimum is not below the maximum; the Graph Lines document is checked for the same allocator and axis-reference rules its codec enforced.
`GraphConfigurationPersistence` (`src/qt_data/`) implements the new `data::IGraphConfigurationPersistence` port over `ISettingsService`: schema version 4 of the `graph/seriesConfigV1` JSON adds `graphs` and `runAxisLabelSeriesId` beside the version-3 series section; versions 1-3 migrate as before and missing graph sections take defaults. Each section decodes on its own, so an invalid graph section or series section quarantines the raw document and defaults only that section; unparseable or unsupported documents follow the existing quarantine-and-seed path. Custom dates are stored as ISO `YYYY-MM-DD` strings. Saving submits the document without status checks or read-back.
The run graph's axis-label choice that `VisualSettingsManager.qml` stored under `graphAxis/seriesId` is imported through the new `ISettingsService::getLegacyRunAxisLabelSeriesId()` whenever the document carries no choice of its own.
The series JSON codec moved from `SeriesConfigStore` into `series_config_codec` and now validates through `validateRunSeriesDocument()`, sharing `sameSeriesConfigs()` / `sameAxisConfigs()` from the contracts.
`data::GraphConfigurationService` (`src/data/`, Qt-free, over the persistence port) is the single accepted authority: it loads once, holds the committed snapshot as an immutable `shared_ptr<const GraphConfiguration>` with an in-process revision, and `replace()` validates the whole candidate before writing it and installing it. A rejected or unchanged candidate writes and publishes nothing; an accepted one publishes a `GraphConfigurationChange` naming the changed graph keys and whether the Graph Lines series or axis-label sections changed, after the replacement and in revision order even when an observer replaces again.
`IGraphConfigurationUseCase` (`src/app/contracts/`, implemented by `GraphConfigurationUseCase`) exposes the committed snapshot and its subscription, a detached editor seed, `save()` of a complete candidate (rejection carries every issue across all graphs and changes nothing) and `applyQuickPatch()` — a typed per-graph patch of range, averaging window, connection, marker preference, series overrides and axis policies that is validated for its graph before anything is replaced; an empty series override restores that series' defaults.
`SeriesConfigStore` and `ISeriesConfigStore` are retired, so the configuration document has one writer. Graph Lines edits are pure transformations of a caller-owned `RunSeriesDocument` (`run_series_editing.h`, which now also holds `MutationResult` and the edit requests; `StoreMutationFailureCode` became `SeriesMutationFailureCode`, with `ConfigurationRejected` in place of the never-again-reported `PersistenceWriteFailed`). `GraphUseCase` reads series and axes from the committed snapshot and refreshes only on committed Graph Lines changes, so the run graph no longer shows a settings visit's edits before they are saved.
`SettingsViewModel` owns the Settings window's single working copy of the whole `GraphConfiguration` for a visit, with its baseline, unparsed text keyed by graph/group/target/field, the issues of the last rejected Save and the selected graph; `ISeriesManagementUseCase`/`SeriesManagementUseCase` are retired and the view model talks to `IGraphConfigurationUseCase` alone. Opening the window seeds the visit (reopening or refocusing it never reseeds), every Graph Lines edit (series, expressions including the expression editor's result, axis creation and assignment, ordering) is a pure `run_series_editing` transformation of that copy, and nothing reaches the dashboard until Save submits the complete copy once. Unparsed text makes the visit dirty and blocks Save; a rejected Save keeps the copy and reports every issue by location; an accepted Save keeps the window open with a clean baseline. The window footer offers Save and Cancel (Cancel drops edits since the visit began or last saved and closes); the Graph Lines panel's Save Changes/Discard Changes act on the same visit, and its error line now reports validation rejection. Closing with pending changes still offers Save, Discard and Cancel; a clean close releases the working copy.
The Graph Lines Y-axis-label selector edits the working copy (`runAxisLabelSeriesId`) instead of writing `graphAxis/seriesId` from QML; `VisualSettingsManager.qml` no longer persists that key. The dashboard run graph takes the label from committed configuration through `IGraphUseCase::getAxisLabelSeriesId()`/`onAxisLabelChanged()` and `GraphViewModel.axisLabelSeriesId`, still falling back to the first visible series when the choice is empty or names no visible series.
`App`'s injecting constructor takes a `data::IGraphConfigurationPersistence` in place of the series store and exposes `graphConfigurationService()` and `graphConfigurationUseCase()`.
`resolveRange()` (`src/app/contracts/range_projection.h`) turns a stored `RangePreference` into a `RangeProjection` — `NoRelevantHistory`, `EntireHistory`, an inclusive `DayInterval` or a `LatestRunSuffix` — without altering the preference. Recent-N presets span `[end - (N - 1), end]` in the UTC calendar-day model of `ScenarioRunId::startDay()`, ending today or, with the anchor flag on, on the latest relevant run's day (and resolving to `NoRelevantHistory` rather than borrowing another anchor when there is none); custom dates, all history and latest-N ignore the flag. `selectRows()` applies a projection to chronological row days and returns original row indices, so run numbers and identity survive filtering, and `latestDay()` finds the anchor from a graph's full relevant runs.
`data::IDaySource` supplies the current UTC epoch day and announces changes; it is an explicit leaf of `App`'s injecting constructor (exposed as `App::daySource()`). `qt_data::SystemDaySource` reads the system clock on the event loop every 30 seconds and whenever the application becomes active again, announcing each day change once, so today-anchored presets follow the calendar while the app stays open and across sleep.
Both playtime graphs now honour their committed averaging window and range. `PlaytimeGraphUseCase` (daily playtime) and `BenchmarkTrackingUseCase` (benchmark playtime) take the window from `GraphConfiguration`, calculate the rolling series over the full relevant history through the unchanged `rollingTimeAverageFor()` accounting (UTC run-start days, shorter initial denominator, zero-sum days omitted, so a one-day window is the daily totals), and only then project it to the resolved range with `visiblePlaytime()` (`playtime_view.h`), so a value that stays visible keeps its full-history value and no sample is invented past the last run. The daily graph anchors on the newest run of the whole profile and the benchmark graph on the newest contributing run, improving or not. A window change recalculates just that graph's series; a range or style change, or a calendar-day change that moves a today-anchored preset, re-projects the cached series without touching the profile, and benchmark summaries, attainment and rank history are never re-evaluated by either (`IBenchmarkTrackingUseCase::onPlaytimeChanged()`). `rollingTimeAverageFor()` now sizes its output by the history instead of the window.
`PlaytimeGraphViewModel` exposes `title` and `averagingWindowDays`, and `BenchmarkHistoryViewModel::metricName` follows the benchmark playtime window, so titles and series names state the effective window ("Daily Playtime (7-day rolling average)", "Daily Playtime (daily totals)", "Three-day average playtime", "Daily playtime") and a window other than three is never called three-day. A date range spans its whole interval on the X axis, blank days included; the benchmark playtime graph now owns its own date axis, while the rank graph keeps the all-history extent.
The scenario history graph honours its committed range. `CompletionHistoryUseCase` (now taking `IGraphConfigurationUseCase` and `data::IDaySource`) resolves the range against the current scenario's full chronological runs, so the anchor is that scenario's newest run, and returns only the visible rows with `CompletionHistory::full_count` for the whole history; latest-N keeps a suffix, date ranges filter by each run's start-time day, and every row keeps its original one-based `run_index`. `onRangeChanged()` fires for committed changes to the scenario-history graph and for calendar rollovers under a today-anchored preset. `CompletionHistoryViewModel` exposes `runCount` (whole history), `visibleRunCount` and `selectedRunVisible`; the X axis spans the original visible run numbers, tooltips and clicks address original runs, a run the range hides stays selected without a marker, and changing the range never selects a different run. A single visible run now draws its marker and tooltip on a half-run-padded axis instead of the "At least 2 runs" refusal, and the panel says whether the scenario has no runs or the range shows none.
The benchmark rank graph honours its committed range without re-evaluating the benchmark. `BenchmarkTrackingUseCase` resolves it against the newest contributing run (improving or not) into `BenchmarkWorkspaceSnapshot::rank` (`RankRangeView`: interval or no relevant history) and announces range and today-anchored day changes through `IBenchmarkTrackingUseCase::onRankChanged()`; the projection's rank history, summaries and attainment stay unfiltered. `domain::rankHistoryWindow()` windows the full retrospective history into the rank established before the range plus the actual in-range improvements, with their full-history values. `SeriesModel` now separates observations (`points`, the only thing tooltips, hit tests, selection and markers use) from non-selectable `leadingCarry`/`trailingCarry` vertices that `SeriesPainter` draws the line through, so the rank is carried flat into a range from its left edge and held after the last improvement to the right edge without adding a point; nothing is drawn before the first improvement, a range with no improvement still draws its carried rank without a tooltip snapping elsewhere, and the synthetic trailing rank point is gone. The rank graph owns its date axis: a date range spans its interval, while all history keeps the shared default extent, and neither benchmark graph's range moves the other. Tier reference lines and the rank axis keep their full-history peak. `BenchmarkHistoryViewModel` takes a `Content` per update and exposes `historyAvailable`, `observationCount`, `hasCarriedState` and `noObservationsInRange`, and its empty text tells no history apart from an empty range.
`SeriesPainter` draws a connection mode and a pen width per series: `Style::connection` (`Smooth` is the unchanged monotone cubic spline, `Straight` joins consecutive observations and carried vertices with straight segments, `None` draws only the markers and skips carry) and `Style::lineWidth`, with `Style::clip` confining the line and dropping markers centred outside it. A lone observation is always marked, with or without carry. `GraphCanvas` gains a `connectionMode` property (`Smooth`, `Straight`, `PointsOnly`, matching `application::ConnectionMode`; default Smooth) and paints each series at its `SeriesModel::lineWidth` (default 3, today's width). Points only bypasses spacing-based marker suppression and `pointMarkersShown` reports it without touching `pointMarkers`, which stays the line modes' preference, so leaving Points only restores it exactly. Data geometry is clipped to the plot area (a stroke centred on an edge keeps its full width), so fixed bounds that exclude values never draw outside it; tier reference lines keep their own path. Spline vertices and carried geometry are never sampled, hit-tested or marked. `GraphCanvasWithTooltip.qml` passes `connectionMode` through.
Numeric Y axes honour a policy per eligible axis. `axis_policy.h` (`ksv::presentation`) resolves an `application::AxisPolicy` in displayed units: fit visible data hugs the data of just the series currently shown on the axis, start at zero pins the lower bound, and fixed bounds are the exact minimum and maximum (accuracy in percent, playtime in minutes, never widened to nice numbers, with readable interior ticks only) — data outside them is clipped by the canvas. Empty and single-point automatic ranges keep the existing fallback span, and unusable fixed bounds fit the data instead. `CompletionHistoryViewModel`, `PlaytimeGraphViewModel` and the playtime `BenchmarkHistoryViewModel` take `setAxisPolicies(AxisPolicyMap)` (keys `score`, `accuracy`, `counts`, with shots, hits and misses sharing the counts policy; `playtime`); an absent key restores that axis' default, which reproduces today's axes (fit score/accuracy, zero-based counts/playtime), and the policy survives data refreshes. Fitting follows the visible series, so toggling a line refits the axis it shares. The run graph and the benchmark rank graph have no policy and keep their own axes.
Every graph view model now draws its committed preferences, at startup and on every committed change. `GraphConfigurationChange` names which sections of each graph changed (`GraphSectionChange`: range, window, style), and `diffGraphConfigurations()` fills them in, so a graph refreshes only what changed: `CompletionHistoryUseCase`, `PlaytimeGraphUseCase` and `BenchmarkTrackingUseCase` re-project or recalculate on a range or window change only, and a style-only edit no longer re-queries the profile, re-evaluates a benchmark or rebuilds a series. Style travels a separate path: `GraphPresentation` (`graph_presentation.h` — connection mode, marker preference, series overrides over the graph defaults via `seriesStyle()`, axis policies) is exposed by `IGraphUseCase`, `IPlaytimeGraphUseCase`, `ICompletionHistoryUseCase` and `IBenchmarkTrackingUseCase` as `presentation()` plus `onPresentationChanged()`; the benchmark use case serves both of its graphs and announces a combined edit once. `GraphViewModelBase` gains `connectionMode`, `pointMarkers` and a `styleChanged` signal that `GraphCanvas` repaints on; each view model applies the colour and width of its series (`applySeriesStyle()`) and hands its axis policies to the axis code from the same presentation, so the scenario history, daily playtime and benchmark playtime axes follow the committed policies. The run graph takes the connection mode and markers only: Graph Lines keeps its colours and the painter keeps its width. `ScenarioHistoryPanel`, `PlaytimeGraphPanel`, `BenchmarkHistoryCard` and `DashboardGraphCanvas` bind those properties, replacing the history panel's hard-coded markers; with nothing saved every graph looks as before (smooth lines, markers on scenario history only, the existing colours and the width of 3). The rank line keeps the name "Personal-best average rank" and its tier reference lines when recoloured, and a selected scenario or benchmark never changes the style, which belongs to the graph type.
`GraphGear` (`qml/graph/`, `graphGear_<key>` with popup `graphQuickPopup_<key>`) sits in the header of the run graph, daily playtime, scenario history and both benchmark history cards, outside every data-dependent loader so an empty graph keeps its gear; its accessible name and tooltip name the graph ("Daily playtime settings"), and the run graph keeps its "Configure..." Graph Lines entry point. The popup shows only what the graph has: range presets (last 7/30/90 days and all time; scenario history also latest 25/50/100 runs, all runs and a custom latest-run count), the playtime graphs' rolling-average window, the connection mode and the marker toggle (shown on and disabled while Points only is active), then `graphMoreSettings_<key>`. A committed range no preset names (custom dates, a custom count) is displayed as such ("Custom: 2026-08-01 – 2026-08-20", "Latest 37 runs"). `SettingsViewModel` gains `quickSettings` (committed values per graph, notifying on every committed graph change) and `applyQuickPatch(graph, patch)` returning `{accepted, issues}`: each valid control change goes straight through `IGraphConfigurationUseCase::applyQuickPatch()` to committed state, count text is parsed as a whole number in the view model, and invalid text stays in its field with an inline `<field>_error` while the effective value is untouched. Escape or dismissal keeps accepted changes and returns focus to the gear. More graph settings closes the popup and calls `SettingsDialog.openGraph(graphKey)`, which opens the new Graphs category (`categoryItem_Graphs`, page `graphsSettingsPage`) with that graph selected in `graphSelector` and keyboard focus on the first control of its editor; the visit seeds from committed state, so it already holds every quick change.
The Graphs settings page (`graphsSettingsPage`, `GraphSettingsEditor.qml` inside `graphEditorArea`) edits the selected graph's preferences in the visit's working copy. Under the graph selector it shows Data & range, Axes and Series & style, each only when the graph has controls for it: the run graph gets line style, markers and a `graphLinesLink` to Graph Lines (no range or axes, and no series editor); the rank graph gets a range but no averaging or axis fitting; the playtime graphs add the rolling-average window and one axis; scenario history adds latest runs and its score, accuracy and shared shots/hits/misses axes. A visible range is chosen as all time/all runs, recent days (7/30/90 presets or any count), latest runs (scenario history) or inclusive custom dates, with a summary that tells a moving range ("ending today", "ending at your latest recorded run") from fixed dates, and the "End date ranges at latest recorded run" toggle. Axes name the series they apply to and offer fit visible data, start at zero or fixed bounds in the unit shown (percent, minutes). Series rows name each series with a colour swatch (the existing `ColorDialog`), a line width and a Default button; a graph with one series shows it without a selector. Every limit is stated beside its control, and "Reset this graph" stages that graph's defaults without touching Graph Lines or any other graph.
`SettingsViewModel` gains the editing surface: `graphDrafts` / `graphDraft(graph)` (what each control offers and the text it shows — unparsed input verbatim, else the value in the app locale), `setGraphField()` for typed numbers and dates, `setGraphRangeKind()`, `setGraphAnchor()`, `setGraphConnection()`, `setGraphMarkers()`, `setSeriesColor()`, `clearSeriesOverride()`, `setAxisMode()` and `resetGraph()`, and `graphLimits` for the stated limits and the date format. Text is parsed whole in the app locale (a decimal comma in German, no group separators, ISO dates in any locale, dates as calendar values never timestamps); text that does not parse stays as unparsed input at its field, survives graph and category switches and the Graph Lines round trip, blocks Save and is dropped only when the range kind or axis mode that showed it changes. `draftIssues` validates the working copy as it is edited so every error sits beside its control; Save remains the authority. A rejected Save lists each issue as "Graph › Group › Control" (for example "Daily playtime › Data & range › Rolling average") above the groups, switches to the first issue's graph and focuses its control, and the list clears once the last one is fixed. The editor scrolls inside the settings window so the selector, groups, Save and Cancel stay reachable at the 680x460 floor and larger text scales, and controls tabbed out of view are scrolled into view.
Empty graphs now say which kind of empty they are, and every one keeps its gear. `PlaytimeGraphViewModel` exposes `historyAvailable`, `visibleSampleCount`, `noObservationsInRange` and `emptyStateText` beside `hasData`, so "No playtime recorded yet." (no history at all) is told apart from "No playtime in the selected range."; the scenario history panel does the same from `runCount` and `visibleRunCount`, and each benchmark card from `historyAvailable` and `noObservationsInRange`. A range that hides recorded activity adds a `GraphRangeHint` ("Use the graph settings button to widen the range.") and never falls back to all history or invents activity; an anchored range with no relevant run (no contributing benchmark run) reads as the ordinary no-history state, not an empty range. `BenchmarkHistoryViewModel::noImprovementPoints` is true in Points only when a range carries an established rank but holds no improvement, and the benchmark card then explains that the range has no improvement points and which line styles would draw the carried rank. The run graph keeps its distinct "No run selected." and "Selected run does not support performance analysis." states and the benchmark workspace keeps its completeness gates (an incomplete benchmark still shows no rank card and only its playtime card with a gear), with configuration reachable from the gear or the Graphs page without creating data.
Keyboard and screen-reader pass over the gear popup and the Graphs page. The popup is a named dialog ("Daily playtime quick settings") whose number fields describe their limit until an error replaces it with the message, shown as text in an alert-role label beside the field; "More graph settings" names the graph; Tab walks the popup's controls in reading order and Escape or the close button leaves from any of them, returning focus to the gear. The selected range preset on the Graphs page is bold and described as selected rather than only highlighted, and opening the page from a gear places focus on the first control of the chosen graph's editor instead of the graph selector, which stays one Shift+Tab away.

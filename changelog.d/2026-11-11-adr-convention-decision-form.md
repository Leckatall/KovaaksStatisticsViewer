ADR conventions now say how a decision must be written, and how an accepted ADR is amended or withdrawn.
`docs/conventions/architecture-decision-records.md`: the Decision section opens with the choice in sentences, stated as a rule about responsibilities, ownership, layers or interfaces, with a rename-or-refactor test that sends design detail to the Architecture Description. Scope gains a reversibility test for what counts as one decision and states the division of labour between ADRs and the Architecture Description. Consequences must state at least one cost and exclude signatures and construction order.
ADRs are never deleted and there is no status for a poorly written record; such a record is replaced through supersession, which may now re-record an unchanged decision. A split names one primary superseding ADR that links the others, so `superseded-by` stays a single identifier.
A new append-only `## Amendments` section, added last and only after acceptance, is the one place anything is said about an accepted ADR: a stale-reference correction, a minor adjustment below the significance threshold, or a pointer to an amending ADR. An amending ADR declares the new `amends` frontmatter list and the amended ADR stays `accepted`. This replaces the earlier undefined "amendment or related decision" wording. A new `deprecated` status marks a decision withdrawn without replacement.
`scripts/arch_doc.py` enforces the new rules. `validate adr` accepts `deprecated` (which requires an Amendments section and forbids `superseded-by`), accepts `## Amendments` only as the last section with every entry a list item beginning `YYYY-MM-DD: `, and reports an `amends` target that is missing or whose Amendments section does not name the amending ADR. `adr record` gains a repeatable `--amends NNNN:NOTE` that writes the `amends` list and appends the dated entry to each amended ADR in the same write, creating the section when absent; it refuses a body that already has an Amendments section, a target that is not `accepted`, and a target that is also being superseded. There is no command for deprecating an ADR; that remains a hand edit checked by `validate adr`.

`ScenarioEvaluation` now holds per-run series for the run sequence it was built from: `personalBestHistory()` (`PersonalBestEntry { scenarioRun, score }`, the first run and every strictly better one, so ties keep the earliest run) and `recentAverages()` (one rolling `kRecentRuns` mean per run, re-summed oldest first). `personalBest()`, `personalBestTime()` and `recentAverage()` are read off the last entries, so they agree with the series by construction.
`ScenarioBenchmarkEvaluation` gains `normalizedRecentRank()` (stored beside `normalizedRank()`, 0 without runs or without a ladder) and the computed-on-call `normalizedPersonalBestHistory()` (`NormalizedPersonalBest { scenarioRun, normalizedRank }`) and `normalizedRecentAverages()`.
`AverageRankPoint` is renamed `AverageRankOfDay`; the new per-run point is `AverageRankAfterRun { start, benchmarkRun, averageRank }` with `day()` its UTC day. `Benchmark::averageRankHistory()` and `recentAverageRankHistory()` are now per run: a PB point for every member run that set a raw PB in its BenchmarkScenario (even one above the top tier that leaves the normalised value where it was), and a recent point for every member run.
`rank_history.h` gains `rankHistoryByDay` (the last point of each UTC day), a `RunSpan` overload of `rankHistoryWindow` (`RankHistoryWindow` is now a template on its point type) and `runSpanOfDays` (the member runs on an inclusive range of UTC days, by two binary searches over `memberRunStarts()`).
The history builder walks the run facts once through the same `entriesByHash` bucket map `indexRuns` used, keeping one run count per BenchmarkScenario, so its k-th member run is exactly run k of the sequence that BenchmarkScenario's `ScenarioEvaluation` was built from; it reads each series at that run instead of re-deriving the PB rule and the recent window. Each point is a fresh mean over every BenchmarkScenario in tree order from 0.0, the same order and seed as `averageRank()`, so the last PB point equals `averageRank()` and the last recent point equals the tree-order mean of `normalizedRecentRank()` bit for bit.
`Benchmark::memberRunStarts()` is the start of each member run (index `n - 1` is benchmark run `n`), filled only when the histories are (Trackable with at least one BenchmarkScenario).
`EntrySweep` and its hand-kept duplicate of `ScenarioEvaluation`'s PB and recent-window rules are removed.
`BenchmarkTrackingViewModel` groups both histories by day once per full rebuild (`m_rankByDay`, `m_recentRankByDay`) and draws the calendar axis from them. Day-grouped values match the old running sums up to floating-point rounding.

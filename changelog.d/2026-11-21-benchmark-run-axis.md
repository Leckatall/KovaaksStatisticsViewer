New `RunDateAxis : Axis`, given the UTC start of each visible run, the first visible run's number and the day range for captures. Its bounds are exactly the first to the last visible run (a lone run is padded by ±0.5). Candidate ticks for a period are the first visible run plus every run whose UTC period start differs from the run before it; the period is the shortest of the day-or-longer calendar ladder with no more candidates than the tick target, or the longest. A candidate fewer than `(last − first) / (2 × targetTicks)` runs after the previous kept tick is dropped (a pixel rule is impossible: an axis has no width), and the first visible run's tick is always kept. Tick labels are the run's period start in that period's format; hover is the nearest visible run's UTC date, with the year when the visible runs span two. All calendar arithmetic is UTC.
`CalendarUnit`, `CalendarInterval`, `kCalendarIntervals`, `calendarIntervalFor`, `startOfDay`, `floorDateTime`, `advanceDateTime` and `formatForInterval` moved from `date_time_axis.cpp` into the shared `calendar_interval.h/.cpp`; `DateTimeAxis` behaviour is unchanged.
`BenchmarkHistoryViewModel` now owns its axes (a whole-day `DateTimeAxis` and a `RunDateAxis`) instead of borrowing them from `BenchmarkTrackingViewModel`; `xAxis()` is the one the last `update()` was laid out for (`Content::onRunAxis`), so the axis switch and the content laid out on it are installed together, and `runAxisShown` is exposed to QML.
`BenchmarkTrackingViewModel::rebuildRank` takes a new run path when the graph's committed `xAxis` is the run axis: it finds the run span (`runSpanOfDays` for a date range, the runs up to the anchor day for an anchored all-history range, else every member run), reads the per-run window, places points at their benchmark run numbers, carries an established level in from the span's first run and the last level out to its last run, shows the empty state for a range holding no member run even where the calendar axis would carry a level, and takes the tier scale's peak from the per-run history (a day's runs can rise above its last value).
`applyPresentation()` re-lays out only a rank graph whose committed axis differs from the one it shows, after the first rebuild; a style change that leaves the axis alone still reads no snapshot.
The rank card's canvas adds a `Run: #N` hover row on the run axis, and a capture of a rank graph on the run axis is titled `Date (runs counted in order)` with the day range the axis was given.
